**Breaking:** **The Avro registry client no longer falls back to the Mozilla root bundle** (`spate-avro`)

On Linux and other Unix systems other than macOS, an `https://` registry fails the deserializer at startup when the system trust store yields no usable certificate and `registry.tls.root_ca` is not set. The error is at `registry.tls.root_ca` and names the fixes: install a CA bundle, point `SSL_CERT_FILE` at one, or set `registry.tls.root_ca` to the CA that signs the registry. In previous versions the client logged a warning and verified the registry against the Mozilla root bundle compiled into the binary. An `http://` registry still starts with an empty store, and a redirect or proxy that takes it to `https://` now fails the handshake with a reason that names the system trust store. macOS, Windows and Android keep the operating system's verifier and are unaffected. `spate_avro::TlsSection` is now `spate::tls::TlsSection`, re-exported under the same path with the same field.
