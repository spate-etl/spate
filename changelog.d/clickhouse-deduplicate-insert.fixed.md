**Breaking:** **The ClickHouse sink deduplicates a retried batch whatever `deduplicate_insert` is set to** (`spate-clickhouse`)

On ClickHouse 26.3 and later, the `deduplicate_insert` setting decides insert deduplication over `insert_deduplicate`. The sink sets it to `enable` on every insert, so a retried batch is dropped by its token even when `settings`, the writer's user or profile, or the server default holds `disable`. In previous versions, any of those set to `disable` landed a retried batch twice.

`deduplicate_insert` is a reserved setting, so naming it in the sink's `settings` fails at load. The settings check that `with_row` sends each replica carries it too, so a replica that refuses it fails `with_row` with `SchemaError::Settings`, which names the replica and carries the server's reason. Two cases refuse it: a settings constraint that pins `deduplicate_insert` to another value, and a server older than 26.3, which does not know the setting. In previous versions both started, and the first case landed retried batches twice.
