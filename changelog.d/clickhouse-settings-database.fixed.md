**Breaking:** **The ClickHouse sink refuses `database` in `settings`** (`spate-clickhouse`)

A `sink.clickhouse` section whose `settings` map has a `database` key fails pipeline load with the error `sink.clickhouse: settings."database" cannot be overridden: …`. A sink built in code fails in `build`. In previous versions it loaded, and inserts could go to the table in the database named in `settings` while the startup schema check read the table in the typed `database`. This happened on ClickHouse 26.3, 26.8 and 26.10 when the typed `database` was unset, and on 26.8 and 26.10 when it was set. So rows could reach a table that was never checked, and a table there with the same name and compatible columns took them without an error. Set the database with the typed `database` field.
