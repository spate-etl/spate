**The ClickHouse sink fails an insert the server answers with `TOO_LARGE_ARRAY_SIZE` or `TOO_LARGE_STRING_SIZE`** (`spate-clickhouse`)

An insert whose body is over one of the server's size limits is now a fatal error, handled as any fatal sink write is. In previous versions the batch retried until the drain deadline. Under `format: rowbinary` the sink's own encoder reaches these answers when a record's String value is over `format_binary_max_string_size`, or an Array or Map value is over `format_binary_max_array_size`. A caller's own `RowEncoder`, or frames passed to `write_batch` directly, can also write a block header over the server's limits. A function a materialized view runs on the rows, a damaged stored part, or a replica whose profile sets a lower cap also answers these codes and now stops the sink, where a retry could have reached another replica.
