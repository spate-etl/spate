**`run` returns when a pipeline thread does not stop** (`spate-core`)

`run` waits for each pipeline thread until 500 ms past the deadline the drain set for them. It then logs each thread still running at `ERROR` with the time since it last went round its loop, and returns while that thread runs on. A run that had otherwise completed exits `Failed` with the component `driver-N` for the first such thread; a run that had already failed keeps its own report. In previous versions `run` waited for the thread with no bound, so a lane whose `poll` blocked past its timeout during a shutdown kept `run` from returning. A thread held in a call ends once the call returns, and one that loops without taking its shutdown message runs until the process exits. Pipeline threads also log to the `tracing` subscriber that is the default on the thread that calls `run`.
