**A gauge for how busy the I/O runtime is** (`spate-core`)

Each pipeline exports `spate_pipeline_io_busy_ratio`, the fraction of time the I/O runtime's async workers spent running tasks, from 0 to 1, averaged over the trailing 60 seconds and updated every 5. Previously no metric showed when those workers were the limit, so a saturated I/O runtime looked like a slow sink. When a full 60-second window averages 0.9 or above, the pipeline logs one warning that names `pipeline.io_threads`. A worker's busy time is published at its maintenance tick or when it parks, so a task that holds a worker for a long poll shows up late and in steps, and polls of a second or more can read unevenly. The gauge does not count the blocking thread pool.
