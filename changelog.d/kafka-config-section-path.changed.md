**Kafka configuration errors start at the path of the key they refuse** (`spate-kafka`)

An error from the Kafka source, sink or feed configuration starts with the path of the key it refuses, then a colon, such as `source.kafka.topic: must not be empty`, `sink.kafka.topic: must not be empty` or `feed.kafka.topic: must not be empty`. A sink built from a `sinks:` entry with `spate_kafka::sink::from_component_config` names the entry, such as `sinks.eu.kafka.topic: must not be empty`. An error that names no single key, or whose text already names its key, starts at the section, such as `sinks.eu.kafka: rdkafka."acks" cannot be overridden: …` or `sink.kafka: producer creation failed: …`. A sink built in code with `spate_kafka::sink::build` reports at `sink.kafka`. The source's and the sink's errors are now `ConfigError::Component`.

In previous versions the source wrote `invalid configuration: source.kafka.topic must not be empty` and the sink wrote `invalid configuration: sink.kafka: topic must not be empty`, both as `ConfigError::Validation`, and a sink built from a `sinks:` entry did not name the entry. The feed wrote ``feed.kafka: `topic` must not be empty``. Code that matches these errors by variant or by text needs updating.
