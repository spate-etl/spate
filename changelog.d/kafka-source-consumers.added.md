**The Kafka source can run several consumers per process** (`spate-kafka`)

`source.kafka.consumers` sets how many consumers the source runs, default `1`. Each consumer is a separate member of the consumer group with its own share of the partitions, and each adds one fetch in flight per broker it reads from. Previously the source always ran one consumer, so every partition was fetched through one connection per broker. Raise the count when the source is bound by fetching, as the Kafka source tuning page describes; on one measured setup two consumers raised throughput by 22% and four by 11%. With more than one consumer, consumer `k` sends `client.id` with a `-k` suffix, so a broker quota keyed on the unsuffixed id does not apply to it, and the `spate_kafka_source_*` series carry a `client="consumer-k"` label. `group.instance.id` requires `consumers: 1`. With the default of `1`, the client id and every metric series are unchanged.
