**Dropping the Kafka source returns with an assignment queued** (`spate-kafka`)

Dropping the Kafka source returns when librdkafka has an assignment queued. The source also serves each consumer's queue before releasing it, so a revocation already queued is answered before the close. In previous versions, a queued assignment could leave a consumer's close waiting forever, so `run` never returned. This needed a consumer with no group leave pending: one the group had fenced, one with a `group.instance.id`, or one whose coordinator was unavailable. On such a consumer, a revocation that queues during the drop can still leave its close waiting. Offsets were not at risk, because the final commit had already run.
