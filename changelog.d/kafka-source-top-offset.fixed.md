**Kafka source and a record at offset `i64::MAX`** (`spate-kafka`)

The Kafka source now stops with a fatal error when a broker returns a record at offset `i64::MAX`, the top of the offset range. The position that commits past a record is one above its offset, and none exists above this one. In previous versions the pipeline's controller thread panicked on such a record in a build with overflow checks on. In a release build the committable position wrapped to `i64::MIN`, so the source committed nothing more for that partition. In both versions the partition was read again from its last commit after a restart, and no record was lost. The source now stops again at the same record on each restart, until the group's committed offset is moved past it.
