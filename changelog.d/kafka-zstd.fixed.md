**Kafka reads and writes zstd batches** (`spate-kafka`)

The Kafka source and the Kafka feed read zstd-compressed batches, and the Kafka sink accepts `compression: zstd`. In previous versions librdkafka was built without zstd. The source retried a zstd batch forever: it logged a warning, read nothing further from the partition, and the health probes stayed healthy. Where the group had committed an offset for the partition, no record was lost. The committed offset did not move past the batch, and an upgraded pipeline on the same group resumes from it. A partition the group had never committed starts under `auto.offset.reset`. With the default, `latest`, an upgraded pipeline skips the zstd batch and every record written before it starts reading the partition. With `earliest`, it reads the partition from the start. The sink failed to create its producer for `compression: zstd`. A batch in a codec librdkafka cannot read fails the pipeline with a fatal error, before any record after it is delivered, and so does a batch in a message format it does not know, read from its first record. librdkafka's error text for it is part of the error.
