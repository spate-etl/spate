**Kafka reads and writes zstd batches** (`spate-kafka`)

The Kafka source and the Kafka feed read zstd-compressed batches, and the Kafka sink accepts `compression: zstd`. In previous versions librdkafka was built without zstd. The source retried a zstd batch forever: it logged a warning, read nothing further from the partition, and the health probes stayed healthy. No record was lost, because the committed offset stayed at the first record of the batch, so an upgraded pipeline on the same group resumes from there. The sink failed to create its producer for `compression: zstd`. A batch in any codec or message format librdkafka cannot read fails the pipeline with a fatal error, before any record after it is delivered. librdkafka's error text for it is part of the error.
