**A bounded job's lister runs once per job, and a solo instance lists for itself** (`spate-s3`)

`S3Source::list` runs a bounded feed job's lister: the workers' binary calls it once per job in lister mode, with the `feed:` section and the feed built from it, and builds no sink. It lists the prefix once and publishes one unit per object or byte range. It checkpoints the last listed key whose units, and those of every key before it, the feed has confirmed, and a later run lists after that key. Once the feed has confirmed every unit, it writes an object named `end` at the job location holding an id for the run. A unit the feed rejects as retryable is published again after 1, 2, 4 and 8 seconds, and a unit still rejected, or one the feed refuses, fails the run, which writes no `end`. A file or S3 directory-bucket source keeps no checkpoint and lists the whole prefix on every run.

Worker replicas on a durable feed never list. `S3Source::list` refuses the in-process feed, and a section with no `location`. On `feed: { memory: {} }` the S3 source starts its own lister when it opens and logs a WARN that the run lists and reads the prefix from the beginning, since that feed keeps nothing across a restart.
