**A queue the sink keeps up with no longer pauses the source** (`spate-core`)

A rejected `try_send` to a shard queue pauses the pipeline thread's lanes at once only while a shard worker waits for an `inflight.max_per_shard` slot, which means the sink is the limit. While every worker can take work, the thread retries the push and keeps reading, and pauses only once rejections have lasted `backpressure.min_pause` with no push or flush completing. In previous versions every rejection paused the lanes for at least `min_pause`, so a small queue filled by many threads duty-cycled the source while write permits sat idle. The queue still fills, and `spate_queue_full_events_total` counts each retry, so it rises under contention where `spate_backpressure_pause_events_total` falls. A saturated sink still pauses the source at once.
