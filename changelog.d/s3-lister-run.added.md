**A lister run publishes a bounded job's units** (`spate-s3`)

`S3Source::list_once` lists the source's prefix once and publishes one unit per object or byte range to a durable feed that `main()` builds from the `feed:` section. It reads the workers' own pipeline file and builds no sink. It keeps its checkpoint at the job location and resumes after it, so a run that stops publishes the units after the last checkpoint again. Once the feed has confirmed every unit and the last checkpoint is written, it writes `end` at the location, holding an id fresh to the run; a run that fails writes none, except when the store kept the marker and its reply was lost. A unit the feed rejects as retryable is published again, up to five attempts, and one still rejected or refused fails the run. On the in-process feed a run lists its own prefix, keeps no checkpoint, lists and reads the prefix from the beginning after a restart, and says so in a startup WARN. Two lister runs at two locations publish every unit twice, and nothing detects it.
