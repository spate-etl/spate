**The S3 source reads a lane's next window while it hands on the current one** (`spate-s3`)

When a lane starts handing on a GET window, the source starts the GET for the next window. At the last window of an object in a unit, it reads the first window of the next object instead. In previous versions the next GET started only once the current window's last chunks fit the lane's hand-off of four chunks, so a lane with the default `chunk_bytes` of 512 KiB could wait on its next GET. The read-ahead no longer depends on `chunk_bytes`, and a lane still has at most one GET in flight. A lane can hold three windows, about `3 × units_held × prefetch_bytes` in total, or 48 MiB per pipeline thread at the defaults (32 MiB in previous versions). Lower `prefetch_bytes` or `units_held` to keep the previous footprint.
