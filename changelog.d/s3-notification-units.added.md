**The S3 source reads storage notifications from its feed** (`spate-s3`)

On the feed path, the S3 source reads storage notifications as well as the units a lister publishes. It reads an S3 `Records[]` message, the same records inside the envelope RustFS sends, and the S3 test event, which it acknowledges with nothing to read. Each `ObjectCreated:*` record becomes one part of the message's unit. Its key is decoded as `application/x-www-form-urlencoded`, and its ETag is sent quoted in `If-Match`. Records whose `eventName` creates nothing are dropped, and so are created objects of size 0 in the source's bucket, under its prefix and with a key that decodes. The message is failed back to the feed, which dead-letters it at its cap, when any record has no `eventName` or one that is not a string, when any created record lacks `s3.bucket.name` or `s3.object.key`, carries a field of the wrong type, names another bucket, a key outside the source's prefix, no size, or a key that does not decode, or when a created object of one byte or more has a key that `object_store` cannot read under its own name or an ETag that `If-Match` cannot carry. The message is acknowledged once, after every part has been read. An object announced by both a listing and a notification is read twice.
