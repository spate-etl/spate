**`simd` decoding agrees with `serde_json` on four more inputs** (`spate-json`)

Under the `simd` feature, a string holding a lone surrogate escape such as `"\ud800"` is now a malformed decode error. In previous versions it decoded as a NUL character, so the record reached the sink with different text. An array longer than the tuple or fixed-size array it decodes into is now malformed; previously the extra elements were dropped. An integer map key written as `"+1"` or `"01"` is now malformed, and an `i128` or `u128` map key now decodes. Each case now matches the default `serde_json` backend. Under `on_error: skip` the record is dropped, or the whole payload with `array` framing, and under `on_error: fail` decoding fails.
