# Coordination stores

A **coordination store** is the shared key-value store that a broker-less
source's replicas meet in. It carries the plan, the split records, and the
leases, never records. A source that brings its own group protocol needs none
of this; a source that does not gets its scale-out story from
[source coordination](../../02-concepts/07-source-coordination.mdx) and one of
the stores below.

| Store | `store:` key | Feature on `spate` | Summary |
|---|---|---|---|
| [NATS JetStream](nats/README.mdx) | `nats` | `coordination-nats` | The production backend. Two KV buckets per job; leases ride per-message age limits. |
| [DynamoDB](dynamodb/README.mdx) | `dynamodb` | `coordination-dynamodb` | One table, no servers to run. Watches poll, and each worker judges lease expiry on its own clock. |
| In-memory | `memory` | none for the section; `coordination` to build one in code | A process-local store, never shared between processes. Correct and self-terminating, but progress dies with the process. A coordinated source runs solo over one when the pipeline has no `coordination:` section; `store: { memory: {} }` runs it with the section's tuning, such as `max_in_flight`. Its body takes no keys. Tests build one in code to share between instances in one process. |

A store is selected under `store:` in the pipeline's
[`coordination:` section](../../07-reference/configuration.mdx#coordination),
next to the coordinator's tuning. Its body is the store's own configuration,
documented on its page. The stores live in `spate-coordination`.

A store built in code, such as a custom one, goes to the source through a
`StoreCoordinator` passed to its `with_coordinator` builder, in place of the
section.

Custom stores implement
[`CoordinationStore`](https://docs.rs/spate-coordination/latest/spate_coordination/store/trait.CoordinationStore.html).
Its store operations are `create` (if absent), `update` (revision CAS), `get`,
`delete` (optionally revision-guarded), `watch`, and `list`. The
[store module contract](https://docs.rs/spate-coordination/latest/spate_coordination/store/index.html)
specifies revision ordering, TTL expiry, watch delivery, and reconciliation.
A store with no push notifications backs `watch` by listing at an interval and
declares so through `watch_mode`; the coordinator then watches fewer keys and
reads the split records it needs.
At startup, `StoreCoordinator` probes create-if-absent, revision CAS on update,
and revision-guarded delete in both keyspaces.
