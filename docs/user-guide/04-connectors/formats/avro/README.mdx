# Avro format

The Avro deserializer (`spate-avro`, feature `avro` on the `spate` facade)
decodes bare Avro datums carried by a source into records, either serde types
or dynamically-typed values. Several framings are supported; the framework
handles the framing bytes, so schemas and structs only ever describe the datum
itself.

Construct it from the pipeline's opaque section, handing it the builder's
I/O runtime handle (the registry fetcher lives there):

```rust file=crates/spate/examples/kafka_avro_to_clickhouse.rs region=deserializer
```

That is from
[`kafka_avro_to_clickhouse.rs`](repo:crates/spate/examples/kafka_avro_to_clickhouse.rs),
a complete program that builds under the `full` facade feature. The
`deserializer:` section is optional in the framework's config, so the factory
takes the unwrapped section, and a pipeline whose source emits ready-made
records configures none.

## Configuration

The `deserializer: { avro: ... }` section deserializes into `AvroSettings`
([`spate-avro/src/config.rs`](repo:crates/spate-avro/src/config.rs)); unknown
fields are rejected with the offending key.

```yaml
deserializer:
  avro:
    mode: confluent                # confluent | raw | single_object
    registry:                      # required for confluent
      url: ${SCHEMA_REGISTRY_URL}
      username: ${SR_USER}         # optional basic auth
      password: ${SR_PASSWORD}
    prewarm_subjects: [orders-value]
    negative_cache_ttl: 30s
    reader_schema:                 # optional: pin the resolved shape
      path: /etc/spate/orders.avsc   # (or `inline: '{"type": ...}'`)
    # schema: { inline | path }    # required for raw / single_object
```

| Key | Type | Default | Description |
|---|---|---|---|
| `mode` | string | `confluent` | Payload framing: `confluent`, `raw`, or `single_object`. |
| `registry.url` | string | `required` | Base URL of a Confluent-compatible schema registry. Required in `confluent` mode; rejected in the others. |
| `registry.username` / `registry.password` | string | `none` | Basic auth (interpolate secrets via `${VAR}`). |
| `prewarm_subjects` | string list | `[]` | Subjects whose latest schemas are fetched at startup (`confluent` mode only). |
| `negative_cache_ttl` | duration | `30s` | How long a schema id the registry could not serve stays negatively cached before a refetch is allowed. |
| `reader_schema` | `{ inline }` or `{ path }` | `none` | Reader schema pinning the resolved record shape (`confluent` and `raw` modes; not `single_object`). |
| `schema` | `{ inline }` or `{ path }` | `required` | The writer schema. Required in `raw` and `single_object` modes; rejected in `confluent` mode (writer schemas come from the registry there). |

Mode requirements are validated at construction with explicit messages:
`confluent` without a `registry`, `raw` without a `schema`, `prewarm_subjects`
outside `confluent`, and so on all fail fast at startup.

## Security (registry credentials)

`registry.username` and `registry.password` carry basic auth to the schema
registry. Interpolate them from the environment (`${SR_USER}` / `${SR_PASSWORD}`)
rather than committing them; an authentication failure against the registry is
fatal at startup, not retried indefinitely. See
[Securing connections](../../../03-guides/securing-connections.mdx) for the
generic model.

## The three modes

- **`confluent`** — Confluent wire format: each payload starts with a
  5-byte header (magic byte `0` plus a 4-byte schema id) followed by the
  datum. The framework parses the header, resolves the id against the
  registry, and decodes; producers using Confluent-ecosystem serializers
  work without adaptation.
- **`raw`** — bare datums with a fixed configured schema (`inline` or a
  mounted `.avsc` file).
- **`single_object`** — Avro single-object encoding (marker plus Rabin
  schema fingerprint), verified against the configured schema's
  fingerprint.

## Typed or dynamic records

The builder hands out these deserializer flavors:

- `build_serde_datum::<T>()` (and the record-family form `build_datum::<F>()`)
  — decodes each datum **directly** into `T` in a single pass, driven by the
  writer schema, never materializing an intermediate value tree. This is the
  throughput path. With a borrowed record family, string and bytes fields
  point straight into the payload buffer (zero-copy;
  [`spate-avro/tests/zero_copy_flat_map.rs`](repo:crates/spate-avro/tests/zero_copy_flat_map.rs)
  is the worked example).
  The constraints: no `reader_schema` (rejected at build time, since records
  decode in the writer schema's shape; additive evolution works through
  `#[serde(default)]`/`#[serde(alias)]`, and unknown fields are skipped),
  and no `duration`/`big-decimal` logical types. A fixed schema breaks the
  logical-type rule at build time; in registry mode the writer schema only
  arrives at runtime, so an incompatible schema id surfaces **per record**
  as `SchemaUnavailable`, dropped and counted under the Skip policy and fatal
  under Fail, while the same id stays fully decodable on the paths
  below.
- `build_serde::<T>()` — decodes each datum into a
  `T: serde::de::DeserializeOwned` struct via an intermediate `AvroValue`,
  applying Avro's full schema-resolution rules when a `reader_schema` is
  configured (field reordering, type promotions, defaults, aliases).
  This is the flavor the construction snippet above builds.
- `build_value()` — decodes into dynamically-typed `AvroValue` records, for
  pipelines that inspect or route on structure not known at compile time.

## Schema fetching never blocks a pipeline thread

In `confluent` mode, registry schemas are fetched by an **asynchronous task
on the I/O runtime** and cached per process. When a payload references a
schema that is not cached yet, the deserializer does not wait: it reports
"not ready", the operator chain holds the batch (backpressure pauses the
source if needed), and **the batch retries once the fetch lands**. Records
are never dropped or duplicated by this mechanism, and the CPU-pinned
pipeline threads never perform I/O. These knobs shape the edge cases:

- `prewarm_subjects` fetches the configured subjects' latest schemas at
  startup, so the first batch does not pay the miss.
- Ids the registry *cannot* serve are negatively cached for
  `negative_cache_ttl` and then handled by the deserializer's
  `ErrorPolicy` (Skip or Fail) like any other poison payload, so a permanent
  bad id cannot wedge the pipeline into an infinite retry.

## Error handling

Undecodable payloads follow the deserializer's `ErrorPolicy`, Skip or Fail,
like any other poison payload: Fail stops the pipeline on the first bad datum;
Skip drops it and continues. A schema id the registry cannot serve reaches the
same policy once its negative-cache entry expires, so a permanently bad id is
an error rather than an infinite retry.

The unit is the payload. One datum is one record here, so there is no partial
outcome to reason about. Drops surface in the framework's stage families,
below.

## Schema evolution

Writer schemas come from the payload (registry id or fingerprint) or
configuration; an optional `reader_schema` pins the shape records resolve
into, using Avro's standard schema-resolution rules: field reordering,
defaults for missing fields, type promotions, aliases. Pin a reader schema to
keep a struct stable while producers evolve. Registry schemas using schema
references are not supported yet and surface as unavailable.

## Metrics

This deserializer registers no families of its own. Decode outcomes surface in
the framework's stage families: `spate_deser_records_total{outcome}`,
`spate_deser_records_dropped_total{reason="skip_policy"}`, and
`spate_deser_not_ready_total` for payloads held waiting on a registry fetch,
which is neither an error nor backpressure. See [Metrics](../../../../METRICS.md).
