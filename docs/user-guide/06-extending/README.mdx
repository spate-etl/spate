# Extending

This section is for library users building their own components, whether
connector authors or anyone whose pipeline needs more than the shipped
connectors.
The framework's abstractions were sized for that case:
small, stable traits at the edges, with batching, retries,
acknowledgments, checkpointing, and backpressure all owned by the engine so
your component doesn't have to be.

The contracts these pages implement are specified in
[The v1 contracts](contracts.mdx), which also covers the erasure boundary they
all meet at; exact signatures live on
[docs.rs](../07-reference/README.mdx). Every page mirrors a runnable
example under [`crates/spate/examples`](repo:crates/spate/examples).

## [The v1 contracts](contracts.mdx)

The traits every component here implements, and the single erasure boundary
that shapes them: why a record can borrow from the source's buffers and still
cross into a trait object, how a blocked push distinguishes sink pressure from
an upstream dependency, and what `RecFamily` is working around.

## [Custom sources](custom-source.mdx)

Implement `Source` (the control plane: lifecycle, lane assignment events,
commits, pause/resume) and `SourceLane` (the data plane: poll borrowed
payload batches, one `AckRef` per batch). Covers the contracts that keep
sources live under backpressure and correct across rebalances.

## [Custom sinks](custom-sink.mdx)

Implement `RowEncoder` (the CPU half: record to wire bytes, on pipeline
threads) and `ShardWriter` (the I/O half: sealed batch to replica endpoint,
on sink workers), then hand them to the builder as `SinkParts`. No trait
impl is required for hand-rolled sinks.

## [Custom operators](custom-operators.mdx)

Operators are stateful closures over `map`/`filter`/`try_map`/`flat_map`, with
no trait to implement, and the whole chain still compiles to one
monomorphized loop. Covers per-stage error policies, zero-allocation
fan-out, and when to drop down to the `Collector`/`StageLifecycle` traits.

## [Instrumenting connectors](instrumenting-connectors.mdx)

Every stage is pre-instrumented by the engine; this page covers where a
connector *adds* to that: feeding a framework handle with signals only it can
see (a source driving `SourceMetrics` for consumer lag), carrying the
standard labels via `with_component_type` / `with_replica_labels`, and
registering your own metric on the same `metrics` facade when the taxonomy
doesn't cover it.

## Prerequisites

You'll want the [Concepts](../02-concepts/README.mdx) section first,

the process your code runs on) and
