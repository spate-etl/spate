# The v1 contracts

The traits your component implements, and the one boundary that shapes all of
them. The other pages in this section show each trait in the context of writing
a source, a sink or an operator; this page is the seam they all meet at, and the
types that only make sense once you have seen it.

Exact signatures live on [docs.rs](../07-reference/README.mdx). What follows is
the shape and, where it is not obvious, why it is that shape — because several
of these look stranger than they are until you know what they are working
around.

Every fence on this page is therefore a trait or a struct quoted to be read
rather than run, abridged to the members under discussion. That is what keeps
them written out here instead of rendered from the compiled source: rendering
one would put a full item on a page whose subject is the shape of it, and the
full item is what docs.rs is for.

## The seam

A pipeline stores its chain as a trait object, so the chain's type is erased
exactly once. That single boundary is `RunnableChain`:

```rust
/// The one erasure boundary. One virtual call per batch.
pub trait RunnableChain: Send {
    /// `from` is the resume cursor: where a blocked push left off.
    fn push_batch<'buf>(&mut self, batch: &mut dyn PayloadBatch<'buf>, from: usize) -> PushOutcome;
    // + flush/drain lifecycle hooks
}
```

The constraint that produced it: a trait object cannot be parameterized by a
lifetime that varies per call, and records here *borrow* from the source's
buffers, so their type is lifetime-parameterized. `Box<dyn RunnableChain>` is
only legal because **no lifetime-parameterized type is ever stored across the
call.** Records are deserialized, transformed and serialized into shard frames
entirely inside one `push_batch` — born and dead within it — so by the time it
returns there is nothing borrowed left to name.

Two things follow that are worth knowing before you design around them:

- Dispatch costs one virtual call **per batch**, amortized over every record in
  it. Everything inside the chain is monomorphized and inlines freely.
- Nothing can hold a record beyond the call. Windowing, sorting and stateful
  aggregation are structurally impossible rather than merely unimplemented.

## Naming a borrowed record: `RecFamily`

A chain still has to name its record type in its own generic parameters, and
that type borrows. `RecFamily` is how a lifetime-parameterized type crosses
generic and `dyn` boundaries:

```rust
/// Lifetime-to-type family. The marker is `'static`; the borrowed type is
/// recovered by projection at each use.
pub trait RecFamily: 'static { type Rec<'buf>: Send; }
```

You write a marker type whose only job is to carry the associated type. Use
`Owned<T>` when your records do not borrow — most user-defined record types do
not, and you never need to think about this again.

This is the least intuitive part of the framework, and its error messages are
poor. If a chain will not compile and the message mentions an associated type
projection, this is usually why.

## Deserializing: one payload in, many records out

```rust
/// Push-style, so a payload yielding many records allocates nothing to
/// return them. Dyn-compatible.
pub trait Deserializer<F: RecFamily>: Send {
    fn deserialize<'buf>(&mut self, raw: &RawPayload<'buf>, ack: &AckRef,
        out: &mut dyn EmitRecord<'buf, F::Rec<'buf>>) -> Result<(), DeserError>;
}
```

Records go out through the emitter rather than back through a return value, so
a payload that contains a thousand records does not allocate a collection to
hand them over.

## Records and what a batch reports

```rust
pub struct Record<T> {
    pub payload: T,
    pub meta: RecordMeta, // Copy: partition, offset, event time, key hash
    pub ack: AckRef,
}
```

`RecordMeta` is `Copy`, so passing it around costs nothing. The `AckRef` is a
clone of the batch's acknowledgment handle — see
[Delivery guarantees](../02-concepts/02-delivery-guarantees.mdx) for what
happens when it drops.

`push_batch` returns a `PushOutcome`. When it reports that it is blocked, the
reason matters, and the two are handled very differently:

| Reason | Means | What the framework does |
| --- | --- | --- |
| `Capacity` | The sink cannot take more right now | Engages the backpressure controller: pauses lanes, keeps polling |
| `NotReady` | An upstream dependency is not available — a schema fetch in flight, say | Retries **without pausing the source**, and counts `spate_deser_not_ready_total` |

Getting this wrong is a performance bug rather than a correctness one, but an
expensive one: reporting `Capacity` for a schema fetch pauses a source that had
no need to pause.

A blocked outcome also carries a **resume cursor**. Records already pushed are
never re-run through the operators when the chain resumes, so a partial batch
costs no duplicated work.

## Operators

```rust
/// Statically composed push stage. map/filter/flat_map monomorphise into
/// one loop.
pub trait Collector<T> { fn push(&mut self, rec: Record<T>) -> Flow; }
```

`CollectorFor<F>` is the family-erased, dyn-compatible form, used by
`flat_map`'s stack-borrowed emitter — which is what makes fan-out allocate
nothing. [Writing operators](custom-operators.mdx) covers this, including the
language limitation that makes `map` and `try_map` need a `map_rec` tier.

## Sinks

The sink half is split so the framework keeps everything generic and your
connector writes one batch to one endpoint:

```rust
pub trait ShardWriter: Send + Sync + 'static {
    type Endpoint: Send + Sync + 'static;
    fn write_batch(&self, ep: &Self::Endpoint, batch: &SealedBatch)
        -> impl Future<Output = Result<(), SinkError>> + Send;
}
```

A `SealedBatch` carries pre-encoded wire frames, row and byte counts, a
deterministic deduplication token, and the acknowledgment handles. Rows are
encoded on the **pipeline threads** by your `RowEncoder`, not here — see
[Writing a sink](custom-sink.mdx) for both halves and for the `Drop` obligation
that comes with holding acknowledgment handles.
