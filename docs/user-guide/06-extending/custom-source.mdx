# Custom sources

A source is two pieces, split on purpose:

- **`Source`** — the control plane. Lifecycle, lane assignment/revocation
  events, watermark commits, pause/resume. Driven by the runtime's
  controller from a single thread.
- **`SourceLane`** — the data plane. A pollable unit pinned to one pipeline
  thread, yielding payload batches that **borrow** the lane's buffers.

The API is poll-based rather than a `futures::Stream`, deliberately: real
source clients (librdkafka) already own their network I/O on their own
threads, and a Stream wrapper only adds waker overhead plus `'static`
bounds that break payload borrowing. Rationale in
[docs/DESIGN.md](../../DESIGN.md) (§ Source abstraction); trait docs in
`crates/spate-core/src/source/mod.rs` and on
[docs.rs](../07-reference/README.mdx).

This page mirrors `crates/spate/examples/custom_source_sink.rs` — a generator
source counting to a limit per partition. Run it:

```sh
cargo run -p spate --example custom_source_sink
```

## The data plane: `SourceLane` and `PayloadBatch`

A lane polls up to `max_records` payloads, waiting at most `timeout`:

```rust
impl SourceLane for CounterLane {
    type Batch<'a> = CounterBatch<'a>;

    fn id(&self) -> LaneId { self.id }
    fn partition(&self) -> PartitionId { self.partition }

    fn poll(
        &mut self,
        max_records: usize,
        timeout: Duration,
    ) -> Result<Option<Self::Batch<'_>>, SourceError> {
        if self.next >= self.limit {
            // Exhausted: block briefly like an idle consumer would — a lane
            // must never busy-spin the pipeline thread.
            std::thread::sleep(timeout);
            return Ok(None);
        }
        let base = self.next;
        let end = (base + max_records as i64).min(self.limit);
        self.buf.clear();
        self.buf.extend((base..end).map(|n| n.to_string().into_bytes()));
        self.next = end;

        // One acknowledgement handle per batch.
        let ack = self.issuer.issue(self.partition, end - 1);
        Ok(Some(CounterBatch {
            payloads: &self.buf,
            partition: self.partition,
            base_offset: base,
            idx: 0,
            ack,
        }))
    }
}
```

What the framework holds you to:

- **Payloads borrow the lane.** `Batch` is a GAT borrowing `'_` from the
  lane, so payloads can point straight into your client's buffers — zero
  copies out of the source. The batch is dropped before the next `poll` on
  the same lane; records derived from it are consumed or encoded within
  that window (the operator chain guarantees this by construction).
- **One `AckRef` per batch.** Issue it through the `AckIssuer` you received
  at `open` (`issuer.issue(partition, last_offset)` — the offset of the
  **last** record in the batch). Every record deserialized from the batch
  clones this handle; the checkpointer advances the partition's watermark
  past the batch only when every clone resolves as delivered. You never
  track individual records.
- **Idle lanes block, never spin.** `Ok(None)` means nothing arrived — but
  reach it by waiting up to `timeout` (a blocking queue read, a condvar,
  worst case a sleep). A zero-timeout poll loop busy-spins a pinned
  pipeline thread at 100% for nothing.

The batch type streams payloads out one at a time, all sharing the batch
lifetime:

```rust
impl<'a> PayloadBatch<'a> for CounterBatch<'a> {
    fn next_payload(&mut self) -> Option<RawPayload<'a>> {
        let bytes = self.payloads.get(self.idx)?;
        let offset = self.base_offset + self.idx as i64;
        self.idx += 1;
        Some(RawPayload { bytes, key: None, partition: self.partition,
                          offset, timestamp_ms: offset })
    }

    fn ack(&self) -> &AckRef { &self.ack }
}
```

`RawPayload.key` feeds the sink's shard routing hash — populate it if your
source has message keys.

## The control plane: `Source`

```rust
impl Source for CounterSource {
    type Lane = CounterLane;

    fn open(&mut self, ctx: SourceCtx) -> Result<(), SourceError> {
        self.issuer = Some(ctx.issuer);   // clone into every lane you build
        Ok(())
    }

    fn poll_events(&mut self, timeout: Duration) -> Result<SourceEvent<CounterLane>, SourceError> {
        if !self.handed_out {
            self.handed_out = true;
            let lanes = /* build one CounterLane per partition */;
            return Ok(SourceEvent::LanesAssigned(lanes));
        }
        std::thread::sleep(timeout);      // nothing else ever happens
        Ok(SourceEvent::Idle)
    }

    fn commit(&mut self, watermarks: &[(PartitionId, i64)]) -> Result<(), SourceError> {
        // Store durably per your source's policy (Kafka: store_offsets).
        Ok(())
    }
}
```

- **`open`** runs once, before anything else, and hands you the
  `AckIssuer`. Connect here.
- **`poll_events`** services control-plane work (rebalance callbacks,
  statistics) and returns the next `SourceEvent` — for a simple source
  `LanesAssigned(lanes)`, `LanesRevoked { lanes, barrier }`, or `Idle`
  (the full set, including the additive and completion events, is under
  [Epochs and rebalances](#epochs-and-rebalances)). The runtime calls it
  regularly **regardless of backpressure state** — pausing data never
  pauses the control plane, which is how group liveness survives a slow
  sink.
- **`commit`** receives per-partition committable watermarks. Each is
  **one past the last acknowledged offset** — store it as-is (this matches
  Kafka's commit convention). Interval-driven; durability is per your
  source's own policy.
- **`flush_commits`** (default no-op) must synchronously flush stored
  positions — the runtime calls it at shutdown and revocation.
- **`pause`/`resume`** (default no-ops) are the backpressure hooks: stop
  and restart fetching for specific lanes. Sources that can't pause rely on
  bounded-queue pushback alone, but a pausable source keeps memory flat
  under sink pressure.

## Framing: turning bytes into records

A source emits `RawPayload`s; a deserializer decodes one payload into records.
For a message source (Kafka) the message boundary *is* the record boundary, so
nothing extra is needed. For a **streaming** source — an object-storage
backfill, an HTTP chunked body, a WebSocket stream — one transfer is a large
byte stream that must be cut into records *before* the deserializer sees them.
That cutting is **framing**. The *seam* is transport-agnostic and lives in
`spate_core::framing`, but the concrete framer is a property of the **format**, so
it is owned by the format crate and handed to a source at assembly time:

```rust
pub trait RecordFramer: Send {
    fn push(&mut self, bytes: &[u8]) -> io::Result<()>;   // fed decoded bytes
    fn finish(&mut self) -> io::Result<()>;               // end of stream/object
    fn pop(&mut self) -> Option<Vec<u8>>;                 // next completed record
    fn decoded_bytes(&self) -> u64;                       // metrics
}
```

A framer **must be a pure function of the byte stream** — the record sequence
must not depend on how bytes arrive in chunks — so a source that resumes by
record index replays deterministically. `spate-json` ships `NdjsonFramer` (NDJSON
line framing) as the format's impl; a future `spate-avro` would ship a container
framer. `FramerWriter` bridges a `Write`-based decompressor to a framer so
compression stays orthogonal. The `spate-s3` source drives this seam and takes the
framer via `S3Source::with_framer` — so the source stays format-agnostic and any
streaming source reuses the same framer.

Tell the framework how your payloads are framed with **`framing_contract`**, so
framing is established once (on the source) instead of coordinating it with the
deserializer by hand:

```rust
fn framing_contract(&self) -> FramingContract {
    FramingContract::PerRecord    // one record per payload → deserializer decodes a single unit
    // default is WholePayload    // whole payloads → the deserializer frames (e.g. JSON ndjson/array)
}
```

The contract reaches the chain as `ctx.source_framing`; a deserializer builder
like `JsonDeserializerBuilder::for_source_framing` uses it to derive its
granularity and reject a double-framing configuration (source frames *and*
deserializer frames). Not every layout fits this model — columnar, footer-indexed
formats (Parquet/ORC/Arrow) have no per-record byte boundary and belong to a
future record-batch reader source, not a framer.

## Epochs and rebalances

Assignment changes are where at-least-once is won or lost:

- **`LanesAssigned` bumps the assignment epoch** in the checkpointer, and
  acks issued under a previous epoch are discarded — a stale ack from a
  revoked assignment can never advance a new epoch's watermark.
- **`LanesAssigned` is eager**: `begin_epoch` replaces all trackers, so a
  `LanesAssigned` event must describe the **full** assignment following a
  full revocation, not a delta. (The controller defensively drains and
  commits live lanes if a source violates this.)
- **`LanesAdded` is the additive alternative**: new lanes join the
  *current* epoch; existing lanes and their in-flight acks are untouched.
  Lane ids must be new — never reuse an id from the source's lifetime —
  and each lane's partition must be fresh, not one revoked earlier in the
  epoch. Coordinated sources emit this for split gains, so a routine gain
  never drains flowing lanes.
- **`LanesRevoked` carries a `DrainBarrier`.** The runtime trips it for the
  owning pipeline threads, which stop the lanes, flush in-flight records,
  and arrive at the barrier. Complete the revocation — final synchronous
  commit included — only after `DrainBarrier::wait` returns. This is the
  choreography that lets a scale-down cost only the uncommitted tail; see
  [Delivery guarantees](../02-concepts/02-delivery-guarantees.mdx).
- **`LanesRetired` removes finished lanes without a barrier** — strictly
  for lanes whose input is fully delivered, acknowledged, *and committed*
  (e.g. a coordinated split whose terminal progress reached the store), so
  by contract nothing unflushed or uncommitted can exist behind them. If
  any in-flight data or uncommitted acknowledgement may remain, use
  `LanesRevoked`.
- **`CommitReady { partitions }` is a latency hint**: the named lanes have
  decided end-of-input, and a commit outside the periodic tick is
  worthwhile now. The runtime briefly tightens its commit cadence for
  those partitions only — bounded by one commit interval — until their
  acks quiesce. Correctness never depends on it.

:::warning
Never block inside `poll_events` waiting on data-plane progress you
yourself gate. The one sanctioned wait is `DrainBarrier::wait` during a
revocation — the runtime guarantees the pipeline threads are draining
toward it.
:::

## Coordination-aware sources

A broker-less source can let several pipeline replicas divide its work by
plugging into the [coordination seam](../02-concepts/07-source-coordination.mdx).
You implement two small traits — *what the work is* and *how to read one
piece of it* — and embed the framework's `CoordinationDriver`, which owns
all of the assignment choreography, fencing bookkeeping, and completion
tracking. Everything below is the complete wiring; the runnable version
is `crates/spate/examples/coordinated_pipeline.rs`.

### 1. Plan the work: `SplitPlanner`

The planner enumerates the input as **splits** — leasable work units with
deterministic ids. It runs only on the fleet's elected leader; workers
receive the descriptors and never re-enumerate.

```rust
use spate::coordination::{
    CoordinationError, PlanContext, PlanFinality, PlannedSplit, SplitId,
    SplitPlan, SplitPlanner, SplitSpec,
};

struct MyPlanner { /* connection/config it plans from */ }

impl SplitPlanner for MyPlanner {
    /// Config-derived job identity (NEVER derived from the enumeration).
    /// Byte-equal across every worker of the job, or the odd one out is
    /// rejected at startup.
    fn fingerprint(&self) -> String {
        "my-source:v1:table=orders".into()
    }

    /// May do real I/O (a LIST, an index scan) — it runs off the async
    /// loop. Idempotency contract: unchanged work yields the same ids.
    fn plan(&mut self, ctx: PlanContext<'_>) -> Result<SplitPlan, CoordinationError> {
        let splits = vec![PlannedSplit::new(
            SplitSpec::new(
                SplitId::new("rows-000000-000125")?,
                b"0..125".to_vec(),          // opaque descriptor, keep it small
            )
            .with_weight(125),               // cost hint (bytes, rows)
        )];
        // Final = bounded job (completion is reachable). Open = the leader
        // re-runs the planner on the replan interval; persist a cursor via
        // `.with_planner_state(...)` and read it back from `ctx.planner_state`.
        Ok(SplitPlan::new(splits, PlanFinality::Final))
    }
}
```

Sizing guidance: roughly uniform-cost splits, tens of MB to ~128 MB (or
the row-count equivalent). Migrating from a pre-coordination checkpoint:
attach it with `PlannedSplit::with_seed(progress)` — seeds are
first-writer-wins and never overwrite live progress. A brand-new source
plans without seeds; an empty `Final` plan completes immediately. (A
source whose legacy checkpoint cannot be mapped onto splits may prefer a
clean cutover instead — see *Retrofitting an existing source* below.)

Two practicalities the signatures don't show:

- **The planner brings its own I/O.** `PlanContext` carries no client and
  no runtime handle — capture both at construction. `plan` runs on the
  blocking pool, so `Handle::block_on(async_listing())` inside it is the
  intended shape (this is how `spate-s3`'s planner runs its LIST).
- **`SplitId`s are `[A-Za-z0-9_-]`, 1–128 bytes, `.` reserved.** Resource
  names (S3 keys, table names) rarely qualify — never embed them. Digest
  them instead: `spate-s3` hashes the sorted member keys *and their ETags*
  plus a packing-version constant (truncated SHA-256, base64url), so
  replans are id-stable, an overwritten object becomes *new* work rather
  than silently matching stale progress, and a packing change retires old
  ids as an explicit epoch.

### 2. Read the work: `SplitSource`

Implement the driver's callbacks on your **lane-assembly context** — the
sub-struct holding what lane construction needs — not on the source
itself, so the driver (a sibling field) and the context borrow disjointly:

```rust
use spate::coordination::driver::{SplitOpening, SplitSource};
use spate::coordination::{SplitId, SplitProgress, SplitSpec};

impl SplitSource for MyCtx {
    type Lane = MyLane;

    /// Materialize the data lane for a gained (or re-assigned) split.
    /// The descriptor the planner wrote arrives verbatim in
    /// `opening.split.descriptor` — decode it here; a worker never saw
    /// the planner run. `opening.resume` is the authoritative committed
    /// progress (already `validate_resume`-checked); start exactly there.
    /// Spawn fetchers here; never block on data. Clone `opening.waker`
    /// into the lane — see the wakeup contract below.
    fn open_split(&mut self, opening: SplitOpening<'_>) -> Result<MyLane, SourceError> {
        let work = MyDescriptor::decode(&opening.split.descriptor)?;
        let resume = opening.resume.map_or(0, |p| p.watermark);
        Ok(MyLane::new(
            opening.lane,
            opening.partition,
            work,
            resume,
            opening.waker.clone(),
        ))
    }

    /// Drift-check carried progress (etag pins, schema versions) against
    /// this instance's view before trusting it. Default accepts.
    /// Rejecting stops the pipeline.
    fn validate_resume(&self, split: &SplitSpec, p: &SplitProgress) -> Result<(), SourceError> {
        let pin = MyResumeState::decode(&p.state)?;      // same payload encode_commit writes
        pin.check_against(&MyDescriptor::decode(&split.descriptor)?)
    }

    /// Snapshot committable progress at an acked watermark. The `state`
    /// payload is yours: version it, round-trip everything the NEXT owner
    /// needs (etag pins, schema versions) — it comes back in
    /// `opening.resume` and `validate_resume`. Mint
    /// `SplitProgress::completed` when this watermark COMPLETES the split
    /// (fully delivered and fully acknowledged — you own that accounting;
    /// the usual shape is "the lane recorded its terminal watermark T at
    /// end-of-input, and this acked watermark equals it").
    fn encode_commit(&mut self, split: &SplitId, watermark: i64) -> Result<SplitProgress, SourceError> {
        let state = self.resume_state_at(split, watermark).encode();
        Ok(if self.terminal_watermark(split) == Some(watermark) {
            SplitProgress::completed(watermark, state)
        } else {
            SplitProgress::new(watermark, state)
        })
    }

    /// Completion sweep for splits that will never produce another
    /// watermark: a split whose members yield ZERO records (empty
    /// objects, an empty id range), or whose final ack landed exactly at
    /// the previous commit. Return `Some(SplitProgress::completed(...))`
    /// when done, `None` while data is in flight — without this, a
    /// recordless split never finishes and the job never completes.
    fn sweep(&mut self, split: &SplitId) -> Result<Option<SplitProgress>, SourceError> {
        let Some(t) = self.terminal_watermark(split) else { return Ok(None) };
        Ok(self.fully_acked_at(split, t)
            .then(|| SplitProgress::completed(t, self.resume_state_at(split, t).encode())))
    }

    /// The split's lane is being retired (lost, fenced, completed, or
    /// shutdown): DETACH its fetcher — never abort it, the pipeline
    /// thread may still be draining the lane. Must not block. This is the
    /// END OF THE TENANCY: the driver never calls `encode_commit` or
    /// `sweep` for the split afterwards, so drop its state here.
    fn close_split(&mut self, split: &SplitId) {}
}
```

Progress must be **split-relative**: a watermark encodes a position
*within the split's own descriptor* (`spate-s3`: member ordinal + record
index), never a position in some whole-input enumeration — the next owner
has only the descriptor to interpret it against. State is per-tenancy:
`close_split` ends one (nothing can follow it, so drop the split's state
there), and a later re-gain is a fresh tenancy — `open_split` rebuilds
from the carried progress.

One more optional callback, **`take_finishing`** (default: reports none),
is a pure latency hint: return the splits whose lanes decided
end-of-input since the last call (the edge, not the level), and the
driver surfaces them as `SourceEvent::CommitReady` — the runtime then
chases their final acks with a temporarily tightened commit cadence
(bounded by one commit interval) instead of waiting out the periodic
tick, so a split completes and frees its working-set slot within
milliseconds of its last record becoming sink-durable. Completion is
correct without it; the terminal commit lands on the next tick either
way.

### 3. Delegate the choreography: `CoordinationDriver`

```rust
use spate::coordination::driver::CoordinationDriver;
use spate::coordination::SplitCoordinator;

struct MySource {
    driver: CoordinationDriver,
    ctx: MyCtx,
    started: bool,
}

impl MySource {
    /// The coordinator is injected, fully built, at assembly time (§4) —
    /// expose this as a `with_coordinator(...)` builder on a config-driven
    /// source. The driver is just a wrapper: `CoordinationDriver::new`
    /// takes the boxed coordinator and nothing else.
    fn new(coordinator: Box<dyn SplitCoordinator>) -> MySource {
        MySource {
            driver: CoordinationDriver::new(coordinator),
            ctx: MyCtx::default(),
            started: false,
        }
    }
}

impl Source for MySource {
    type Lane = MyLane;

    fn open(&mut self, ctx: SourceCtx) -> Result<(), SourceError> {
        self.ctx.issuer = Some(ctx.issuer);
        Ok(())
    }

    fn poll_events(&mut self, timeout: Duration) -> Result<SourceEvent<MyLane>, SourceError> {
        if !self.started {
            self.started = true;
            // Joins the job and returns SourceEvent::LanesAssigned(vec![]) —
            // the EMPTY ready signal. It bumps the controller's assignment
            // epoch and marks the pipeline running while claims race;
            // splits then arrive additively (SourceEvent::LanesAdded).
            return self.driver.start(Box::new(MyPlanner { /* … */ }));
        }
        self.driver.poll_events(&mut self.ctx, timeout)
    }

    fn commit(&mut self, watermarks: &[(PartitionId, i64)]) -> Result<(), SourceError> {
        self.driver.commit(&mut self.ctx, watermarks)
    }
    // flush_commits: keep the default no-op. A commit that returns Ok is
    // either durable in the store or (after a transient store failure)
    // cached by the driver and recommitted on the next tick — the
    // previous durable state stays authoritative meanwhile, so a crash
    // before the recommit only widens replay, never loses data.
}

impl Drop for MySource {
    fn drop(&mut self) {
        self.driver.release(); // graceful release: peers claim instantly
    }
}
```

What the driver owns so you don't: additive gains (each gain mints a
fresh, never-reused lane id and joins the running assignment via
`LanesAdded` — flowing lanes are never drained because a peer's split
arrived); a fresh `PartitionId` per tenancy (so a late drain-commit from
a lost split resolves to a retired tenancy and is skipped — no zombie
folds); the exit split — losses and fences leave through `LanesRevoked`
with the drain barrier, while completed splits leave barrier-less through
`LanesRetired` (their terminal commit already proved nothing is in
flight); fenced-commit triage (`Fenced` → quarantine the tenancy, surface
the loss; `Retryable` → recommit next tick); completion sweeps and the
`take_finishing` → `CommitReady` end-of-input chase; `AllComplete` →
`Drained`. A **stalled** job
(quarantined splits blocking completion) is a fatal error by default —
build the driver with `CoordinationDriver::new(...).stall_drains(true)`
(a consuming builder, applied at construction) to turn it into a
drain-with-warning. Report a poison split you cannot process with
`driver.fail(&mut ctx, &split, "reason")`: it consumes a delivery attempt
and hands the split back (quarantine happens at the attempt cap).

**Poison travels a side channel, never a lane error.** A lane `poll`
error is terminal for the whole pipeline, and `fail` needs `&mut self` on
the source — which a lane, polled on a pipeline thread, does not have. So
an object-level failure (a deleted or corrupt input) must not surface as
a poll error: the lane sends a report over a channel (`std::sync::mpsc`
works; the lane goes quiescent, returning empty polls), and the source
drains that channel at the top of `poll_events`, calling `driver.fail`
for each report before delegating to `driver.poll_events`. `spate-s3`'s
lane/context pair is the production reference.

**Signal the waker on the edges the control plane cannot see.** The
driver — not the backend — owns the control-plane wait, because the two
things worth waking for arrive from different directions: the backend's
events, and *your lanes* reaching end-of-input on pipeline threads. Only
the driver sees both. `SplitOpening::waker` is a `ControlWaker`: clone it
into every lane and call `wake()` on exactly two edges — when the lane
decides end-of-input, and when it reports poison. Both are per-tenancy
edges, never the per-record path.

Signalling is non-blocking, a burst collapses into one wakeup, and a
signal arriving between the driver's check and its park is buffered
rather than lost — so the ordering rule is simply *make the state visible
first, then wake*. Dropping a `wake()` call is silent: the work still
completes, it just waits out a full idle timeout first, so a split's
completion (and the working-set slot it frees) is delayed by up to
`event_poll_timeout` instead of surfacing in microseconds.

The same contract binds a coordination **backend**: `SplitCoordinator::poll`
takes no timeout and must not block — return whatever is pending,
including nothing — and `set_waker` hands over the handle to signal
whenever a later `poll` would return something. There is deliberately no
default `set_waker`: a no-op one would leave the backend parking
internally *and* the driver parking on top.

**How a coordinated job ends.** On a `Final` plan, once every split is
committed complete, every instance — including idle standbys — observes
`AllComplete`; the driver returns `SourceEvent::Drained` and a bounded
runtime exits `ExitState::Completed` with the usual guarantee (every
acked record durably committed). `Stalled` surfaces as a fatal error →
`ExitState::Failed` (or a warned drain under `stall_drains(true)`). An
`Open` plan never reports either — operators stop those jobs with a
signal drain.

### 4. Construct a backend

The coordinator is injected at assembly time, exactly like the framer
seam. Production (NATS, feature `coordination-nats`, server ≥ 2.11):

```rust
use spate::coordination::store::nats::{NatsConfig, NatsStore};
use spate::coordination::{CoordinationConfig, StoreCoordinator};

// One value drives the store's TTL and the coordinator's lease_duration.
// They must match — StoreCoordinator::new fails fast on a divergence
// (heartbeats pace from the config, expiry runs on the store's clock).
let coordination = CoordinationConfig {
    instance_id: std::env::var("POD_NAME").ok(), // unique per replica
    ..CoordinationConfig::default()
};
let store = NatsStore::new(
    // `job`: one per coordinated job — it suffixes the KV bucket names.
    NatsConfig::new(vec!["nats://nats:4222".into()], "orders-backfill"),
    coordination.lease_duration,
)?;
let coordinator = StoreCoordinator::new(
    store,
    coordination,
    pipeline.io_handle(),
    None, // or Some(CoordinationMetrics::new(&labels)) — see below
)?;
let source = MySource::new(Box::new(coordinator));
```

(`NatsConfig::new` gives anonymous plaintext defaults; set `credentials`,
`tls`, and `replicas` on the value for production clusters.)

Tests and single-process runs swap the store — nothing else changes, and
the `coordination` feature alone suffices (no NATS dependency tree):

```rust
use spate::coordination::store::memory::MemoryStore;
let store = MemoryStore::new(coordination.lease_duration);
```

Connection notes: `NatsStore::new` is synchronous — the connection and
bucket provisioning happen lazily under the coordinator's startup retry
budget, so a down NATS at boot retries with backoff and a
misconfiguration (old server, a `lease_duration` changed mid-job, a
store TTL diverging from the coordination config) fails fast with an
actionable message. Credentials never appear in `Debug` output.

### Retrofitting an existing source

A source that already implements `Source` with its own lane dealing and a
whole-source checkpoint retrofits in three moves (this is exactly how
`spate-s3` was converted — read it as the reference):

1. **Extract the lane assembly** out of the source into the sibling
   context struct: everything `open_split` needs to spawn a fetcher and
   build a lane (client, framer/decoder factories, buffers, metrics
   handles). The source keeps only the driver, the context, and config.
2. **Replace self-dealt lanes with driver assignment.** Whatever loop
   dealt the enumerated work across N lanes becomes the planner (the
   enumeration, leader-only) plus `open_split` (one lane per gained
   split). Static assignment, EOF flags, and "all lanes done" logic all
   disappear — the driver owns assignment cycles and completion.
3. **Decide the checkpoint story.** Per-split fenced progress in the
   coordination store replaces the whole-source checkpoint; they cannot
   coexist as two sources of truth. If old progress maps cleanly onto
   splits, seed it (`PlannedSplit::with_seed`); if the old layout is
   keyed by something splits don't preserve (as spate-s3's per-lane
   round-robin manifest was), make a clean cutover — delete the legacy
   path, and let the job fingerprint refuse any config that could
   misread old state.

### Metrics

The `spate_coordination_*` families are framework-owned and pre-registered:
build `CoordinationMetrics::new(&labels)` and pass it to
`StoreCoordinator::new` (metrics are a constructor parameter; there is no
later hook). The `labels` are `ComponentLabels` — at assembly time build
them yourself (after `Pipeline::from_config` has installed the recorder);
a source constructing its own fallback coordinator inside `open` reuses
its meter's: `ctx.meter.as_ref().map(|m| CoordinationMetrics::new(m.labels()))`.
Passing `None` runs without coordination metrics; nothing registers
per-record.

### Testing

`spate-test`'s `scripted_coordinator()` drives your driver choreography
without a store or clock: script gains/losses/quarantines and commit
outcomes (`Fenced`/`Retryable`/`Fatal`), assert on observed commits,
failure reports, and releases; `take_planner()` hands back the planner
your source registered so a test can run it directly and feed its plan
back through `gain(...)`. For the real protocol end to end, run two
sources over one shared `MemoryStore` in a test — the pattern of
`crates/spate/examples/coordinated_pipeline.rs`.
