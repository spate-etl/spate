# Glossary

Precise definitions of the terms used throughout this guide, in
alphabetical order. Where a term names a public type, the exact contract is
in the rustdoc ([Reference](README.mdx)); where it names a mechanism, the
rationale is in the [decision records](../../adr/README.mdx).

### Ack / `AckRef`

The acknowledgment handle for one source poll batch: a clone of a
refcounted `Arc` created **per batch**, not per record. Every record
derived from the batch clones it. `flat_map` children share the parent's, and
multi-output routing clones per output with worst-status merge. Dropping a
record resolves its share, and an intentional drop (a `filter`, a Skip
policy) counts as **success**. When the last clone drops, the batch's
`(partition, seq, status)` reaches the checkpointer over an unbounded
channel, so the ack path can never block behind data.

### `AckSet`

A collection of acknowledgment handles on the sink path (encoded chunks,
worker ledgers, batch accumulators) with the **opposite** drop default:
where a lone record's drop means delivered, an `AckSet` **fails** its
handles on drop and delivers only explicitly, after a durable write. This
is the fail-by-default contract that turns any teardown (a dropped queue,
an aborted worker) into a watermark stall (replay) instead of a silent
commit of unwritten data.

### Backpressure watermarks (high / low)

The hysteresis thresholds on the in-flight byte
[budget](#budget--in-flight-bytes): sources pause when usage crosses
`high_ratio` × budget and may resume once it falls below `low_ratio` × budget
and at least `min_pause` has elapsed. Unrelated to the
[checkpoint watermark](#watermark), which is the same word for a different
mechanism. See [Backpressure](../02-concepts/03-backpressure.mdx).

### Budget / in-flight bytes

The global cap (`backpressure.max_inflight_bytes`) on bytes admitted into
the pipeline but not yet durably written. Charged when records enter the
terminal stage's chunks, released on durable write or failure; current
usage is `spate_backpressure_inflight_bytes`.

### Chain

The operator pipeline one pipeline thread runs: deserializer →
`map`/`filter`/`try_map`/`flat_map` stages → the terminal sink stage
(route, encode, chunk). Statically composed and monomorphized into one
loop; type erasure happens exactly once, at the chain boundary, with one
virtual call per batch. Built by the chain factory you pass to
`Pipeline::chains`, once per pipeline thread.

### Chunk

The handoff unit between a pipeline thread and a shard worker: rows encoded (by
the `RowEncoder`) into a frame targeting `ChunkConfig::target_bytes` (default 64
KiB), then coded by the sink's [frame codec](#frame-codec) if it has one,
carrying its rows' acks as an [`AckSet`](#ackset). A chunk seals when it reaches
the target, on every commit tick (`checkpoint.interval`), or on an idle lull, so
while the pipeline is unblocked, a slow-filling buffer holds its acks for at
most ~one checkpoint period. Workers merge chunks into
[sealed batches](#sealed-batch), so chunk size does not bound insert size.

### Component / `component_type` labels

Two of the three standard labels on every framework metric (with
`pipeline`): `component` identifies the framework component (for example,
`source` for source metrics or `main.deserializer` for a deserializer stage);
`component_type` identifies the implementation, such as a connector type or an
operator kind (`map`, `filter`). See
[Monitoring](../05-deployment/monitoring.mdx) and
[Metrics](../../METRICS.md).

### Contiguity tracker

The checkpointer's per-partition, per-[epoch](#epoch) bookkeeping: a ring
of outstanding batch sequence numbers, from which it pops the contiguous
acknowledged **prefix** and advances the committable
[watermark](#watermark). Out-of-order acks park until the gap before them
closes, which is what makes "never commit past unacknowledged data"
structural. A synchronous, tokio-free, loom-tested module.

### Dedup token

A deterministic string minted per [sealed batch](#sealed-batch)
(`SealedBatch::dedup_token`) and reused unchanged across retries of that
batch. A sink whose destination supports insert deduplication hands the token
over to make **same-boundary retries** idempotent. It does not cover crash
replay, because after restart data re-batches with new boundaries and new tokens
([Delivery guarantees](../02-concepts/02-delivery-guarantees.mdx)).

*Connector mapping:*
[ClickHouse sink](../04-connectors/sinks/clickhouse/README.mdx#deduplication-tokens-and-the-window-warning)
— honored, but silently inert without a server-side dedup window ·
[Kafka sink](../04-connectors/sinks/kafka/README.mdx#delivery-semantics)
— unused; there is no destination-side dedup window to hand it to.

### Drain

The choreography that quiesces data without losing acknowledgments: stop
the affected lanes, flush the chains, force-seal and write out in-flight
sink batches under `checkpoint.drain_timeout`, then commit synchronously.
Triggered identically by SIGTERM (all lanes) and by a rebalance revocation
(the revoked lanes), via a `DrainBarrier` the owning pipeline threads
arrive at. Batches still unwritten at the deadline are abandoned loudly and
replay after restart. On SIGTERM, a source on a feed that
[hands back](#hand-back) first reads on what it holds, inside the same
deadline.

### Epoch

The **assignment epoch** in the checkpointer, bumped on every rebalance
(`Checkpointer::begin_epoch`) so acks issued under a previous assignment
are discarded.

### Feed

The queue a feed-reading source receives [work units](#work-unit) from,
behind the `Feed` trait. A feed delivers each unit at least once. A failed
unit is delivered again under a new receipt. A feed that leases units keeps a
received unit from other readers only while its holder renews it, and
delivers it again once the renewals stop. A unit that reaches the feed's
delivery cap moves to its dead-letter destination. A source acknowledges a
unit only after reading it to its end and after the sink has acknowledged
every record in it. When the unit's input was replaced while it was read, the
source may acknowledge it once the feed holds a unit naming the input's
current state and the sink has acknowledged every record read from it; past
the source's re-enqueue cap it acknowledges the unit without one and counts
it. On a graceful stop, a feed that [hands back](#hand-back) takes the units a
source has not read to its end. The in-process feed (`MemoryFeed`) serves one
instance and keeps nothing across a restart.

### Frame codec

A sink's optional step that turns each sealed [chunk](#chunk) into its wire
form, for example by compressing it, behind the `FrameCodec` trait. It runs
once per chunk, on the pipeline thread that sealed it. Each output decodes on
its own, and outputs concatenated in seal order form a legal body. The
[budget](#budget--in-flight-bytes) and `max_bytes` count the bytes before the
codec.

### Hand back

What a stopping source does with a [work unit](#work-unit) it has not read to
its end: it returns the unit to its [feed](#feed) for another instance to read.
A feed that leases units frees it at once, and a feed whose positions move only
by commit frees it when the worker leaves at the feed's close. A handed-back
unit is not a failure. A feed that counts deliveries toward a dead-letter limit
counts it as any delivery. A source reads the units it holds until 5s before the
[drain](#drain) deadline, the stop reserve, then hands back the rest. A feed
that hands back is one whose `Feed::hands_back` answers `true`.

### Job location

Where a bounded feed job keeps the state every instance of it reads, named by
the `feed:` section's `location` key, such as the job fingerprint its lister
writes. A job on a durable [feed](#feed)
that names one is **bounded**, and its [work units](#work-unit) come from its
lister. A bounded job ends once its lister's end marker holds over a
[settling window](#settling-window) of empty reads of the feed. A job that
names none is **continuous**, its instances read no job location, and it ends
at a shutdown. A job on the in-process feed names none; one on the feed the
runtime built ends once its own lister has finished and the feed reads empty,
and one given a feed in code ends at a shutdown.

*Connector mapping:*
[S3 source](../04-connectors/sources/s3/README.mdx#bounded-jobs-and-the-job-location)
— an object-store prefix outside the source's prefix.

### Lane

The data-plane unit of a source (`SourceLane`): one pollable stream pinned
to one pipeline thread, yielding borrowed payload batches. Lanes map m:n
onto pipeline threads. Lane ids are never reused. `spate_source_lanes_active`
counts them.

*Connector mapping:*
[Kafka source](../04-connectors/sources/kafka/README.mdx#lanes-partitions-on-pipeline-threads)
— one partition queue ·
[S3 source](../04-connectors/sources/s3/README.mdx#sizing-units-against-pipelinethreads)
— one object, byte range or multi-object unit in progress ·
[Datagen source](../04-connectors/sources/datagen/README.mdx#configuration) —
one generator, `partitions` of them.

### Lister

The one run per bounded job that lists the job's input once, publishes its
[work units](#work-unit) to the [feed](#feed) and exits. A fleet's workers
never list. The lister keeps its checkpoint at the
[job location](#job-location), and writes an end marker there once the feed
has confirmed every unit. Every worker reads that marker to end the job. A
solo run on the in-process feed lists its own input.

*Connector mapping:*
[S3 source](../04-connectors/sources/s3/README.mdx#the-lister-run)
— `S3Source::list_once`.

### Partition

The source-side unit of ordering and checkpointing (`PartitionId`).
Watermarks, epochs, and the contiguity tracker are all per-partition.

*Connector mapping:*
[Kafka source](../04-connectors/sources/kafka/README.mdx) — literally the topic
partition ·
[S3 source](../04-connectors/sources/s3/README.mdx#offsets-progress-resume) —
one per lane, with the offset packing member ordinal and record
index within the object or byte range ·
[Datagen source](../04-connectors/sources/datagen/README.mdx#configuration) —
one per generated lane, set by `partitions`.

### Pipeline thread

One of the N plain `std::thread`s (optionally core-pinned) running the hot
path: poll lanes → deserialize → operator chain → route → encode → shard queues.
All CPU work happens here, with zero per-record allocations; I/O lives on
the tokio [I/O runtime](../02-concepts/01-architecture.mdx) instead.

### Replica

One endpoint of a [shard](#shard) (`[shard][replica]` in a sink topology).
Shard workers rotate writes round-robin across healthy replicas, skipping
open circuit breakers; a failed write retries the same sealed batch on the
next healthy replica.

### Sealed batch

The sink's write and retry unit (`SealedBatch`): concatenated pre-encoded
frames plus row/byte counts and a [dedup token](#dedup-token). A shard worker
seals when `batch.max_rows`, `batch.max_bytes`, or `batch.linger` trips, then
writes it via the `ShardWriter`. The framework delivers the batch's
acknowledgments only after the writer returns `Ok`, the durable-ack point, and
fails them if the batch is abandoned.

### Settling window

How long a bounded feed job's [feed](#feed) must read empty, between two reads
of its [lister](#lister)'s end marker naming the same run, before the job
ends: five minutes unless the `feed:` section's `settling_window` sets another.
The same span bounds a worker's wait for the job fingerprint at startup.

### Shard

One partition of the sink's write topology, served by one worker task that
batches, seals, and dispatches up to `inflight.max_per_shard` concurrent
writes across its [replicas](#replica). Records route to shards by key
hash (or by source partition when keyless).

### Watermark

The per-partition committable position: the offset **one past the last**
contiguously acknowledged record. Stored on advance, committed to the
source on `checkpoint.interval`, and committed synchronously on drain. The
at-least-once invariant is that it never passes unacknowledged data; a
failed batch stalls it (alert on `spate_checkpoint_watermark_age_seconds`)
rather than being skipped. Distinct from the
[backpressure watermarks](#backpressure-watermarks-high--low).

### Work unit

One piece of work a [feed](#feed) carries (`Unit`): an id, and an opaque body
the source decodes to find the input it reads. A unit is acknowledged once,
as a whole, and carries no progress, so a unit delivered again is read again
from its start.

*Connector mapping:*
[S3 source](../04-connectors/sources/s3/README.mdx#unit-identity-and-drift) —
one whole object, identified by its key and ETag, or one byte range of a large
object, identified by its key, ETag and range.
